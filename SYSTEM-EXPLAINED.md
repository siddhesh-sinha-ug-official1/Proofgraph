# Part I — How the system actually works

## The one-sentence version

ProofGraph reads source code and formal proofs, builds a typed dependency graph
with content-addressed IDs, and attaches to every declaration a verdict that is
**honest by construction**: `green` can only be produced by a real checker (today,
the Lean 4 kernel), and everything the system does not know, it *says* it does not
know — in typed, probed, named ways.

## The shape: six cells, three membranes

The system was built as six independent "cells", each by a separate build agent,
each maximally instrumented (probes everywhere) and deliberately without a public
interface. Assembly then added three nested membrane layers:

1. **Cell walls** — each cell got a minimal, versioned, typed face (`wall.py` /
   `src/wall.ts`) promoted *over* its diagnostic pins. The pins (probeCatalog /
   dump / history / tap) stay live underneath — you can inspect any cell's
   internals from outside at any time.
2. **Vasculature** — six vessels wiring wall to wall, each with a connector test
   asserting on *both* cells' probe streams, never on return values alone.
3. **The outer wall** — one function, `analyze(source_root, roots) →
   {graph, verdicts, provenance, gapAnalysis}`, plus the human face (the browser
   app) and the machine face (the AI outlet).

The six cells:

| Cell | What it is | Language |
|---|---|---|
| graph-model | The keystone: owns the frozen schema, content-addressed IDs, the graph store, reachability (rustworkx cross-checked against networkx), projections, the round-trip gate | Python |
| capability-layer | *Measures* what a language toolchain can honestly deliver (a P0–P11 probe battery against a live LSP server) and stamps a depth tier: CT (compiler truth), S, G, P. Tiers are measured, never asserted | Python |
| structure-extractor | Source → graph: T1 structure nodes via tree-sitter, T2 resolved edges via per-language "docks" (pyright for Python, the Lean kernel driver for Lean), T3 graph properties | Python |
| editor-shell | The Monaco text projection: verdict gutter, trust-ring, LSP diagnostics, selection bus | TypeScript |
| graph-view | The React Flow graph projection: nodes painted by verdict, leads dashed, edge-set equality enforced through layout | TypeScript |
| byok-arena | The AI outlet's engine: one normalized ModelAdapter over Anthropic/OpenAI/Gemini on the user's own vaulted key | TypeScript |

Around them, assembly code (not cells): the **hub** (Python backend serving
`/graph`, `/analysis`, `/fs`, `/lsp`, `/pins` to the browser), the **app** (the
graph-first IDE shell), **ai** (the outlet server — keys never leave that
process), **outerwall** (`analyze()` + the emergent layer), **vessels** (the seam
tests), **acceptance** (the end-to-end gates), **faultcheck** + **linegate** +
**run_all_suites** (the enforcement machinery).

## The walkthrough: one file's journey

Take `moatpkg/core.py` (or `unused_hyp.lean`). Here is every point it passes:

**1. Capability measurement (cell 2).** Before anything is extracted, the
capability layer answers: *what can this language's toolchain honestly deliver on
this machine?* It spawns the real language server (pyright via npx; the Lean
language server via the pinned toolchain), runs its P0–P11 battery — including
P2, which injects a genuine type error and requires the server to report it — and
stamps a **measured** tier. Python: CT, earned. Lean: CT, earned. Typst: a typed
`unknown-language` refusal. There is no code path that asserts a tier from a
config file.

**2. T1 extraction (cell 3).** Tree-sitter parses the file into structure nodes
(modules, functions, theorems…). Every node gets a content-addressed ID:
`n_` + sha256("node:v0" ␟ lang ␟ kind ␟ canonicalName ␟ file ␟ structural-path)[:16].
The preimage is *structural*, not byte-based — reformatting or editing a body
does not change a node's identity.

**3. T2 resolution (cell 3's docks, gated by the measured tier).** Only at tier
CT may a dock mint `resolved: true` edges — a lower tier physically cannot
(the tier-inflation guard raises). For Python, pyright answers definition lookups
→ `calls` / `imports` edges. For Lean, the **kernel driver** (`Driver.lean`, run
under the pinned v4.31.0 toolchain) elaborates the file and reports, per
declaration: kernel acceptance, `sorry` usage, the axiom set, the resolved
proof-dependency constants, and unused hypotheses. Unresolvable references are
**leads** (`resolved:false`, `unresolved:`+rawName placeholder) — carried in a
separate `leads[]` array, never in `edges[]`.

**4. Verdicts (the guard chain).** Kernel-accepted, sorry-free, no unexpected
axioms (allowlist: exactly propext, Classical.choice, Quot.sound) **and** the
whole file elaborated error-free → `fill: green, origin: "checked", source:
"lean-kernel:v4.31.0:kernelAccepted decl=<name> run=<sha16>"` — where `run=`
resolves to the recorded driver invocation, cryptographically re-checkable.
`sorry` → amber. Elaboration error → red. No checker → unknown. A green without
that attestation chain is rejected at **three independent walls**: cell 3's
schema validation (`unbacked-green`), the model wall's ingest (`fake-green`),
and the editor's own guard (`green-may-never-be-faked`). All three are
fault-injection-tested — we don't believe the guards, we watch them catch
planted forgeries.

**5. Ingest + verification (cell 1's wall).** The model wall *verifies, never
mints*: edge IDs are recomputed from their own fields and byte-compared; node
IDs are format-and-uniqueness checked at the wall, with full preimage identity
closed at the V3 seam test using the extractor's preimage-carrying pins. Leads
in `edges[]` are rejected. The graph is stored; queries (reachable / unused /
sccs / condensation) run on rustworkx with a mandatory networkx cross-check and
a condensation-is-a-DAG invariant.

**6. The emergent layer (outerwall).** `analyze()` fills what no single cell
could: the **OUTLINE ring** per ruling 8 — each node's reflexive-transitive
trust base over resolved edges, worst-case-wins over a frozen 7-token
vocabulary; green fills contribute kind-derived tokens (theorem→`lemma`,
def→`definition` — which is why a green theorem over a green *definition* rings
blue: a definition is an assumption, not a verification); any unknown in the
base caps the ring at unknown; any lead out of the base caps it at unknown *and*
lands in `gapAnalysis.incompleteBases`. Gap analysis (unused / unreferenced /
cycles / reachability) comes exclusively from the model wall's cross-checked
queries; provenance completeness is build-failing (`assert_no_holes`).

**7. Serving (hub).** The hub serves the canonical envelope on `/graph` and the
byte-canonical analysis on `/analysis` — computed on the *same* pipeline object,
so the app's analysis-graph-mismatch guard can hold. The `/fs` endpoints are the
browser's only file access, path-jailed to the declared workspace. `/lsp`
bridges the editor's LSP traffic to cell 2's measured server over WebSocket.

**8. The faces.** The **app** (graph-first IDE shell per the design handoff):
full-bleed verdict canvas, tool windows, Monaco with the verdict gutter, status
bar whose every fact comes from pins or served data. The verdict colors are
canonical imports — a grep for the five verdict hexes in `app/src` returns zero;
your accent color drives chrome only. The **AI outlet** answers questions about
the graph through real tool calls against served data, with keys confined to its
server process (a build-failing bundle scan proves no key material ships to the
browser).

**9. The paper trail.** Every step above emits probe events into per-cell
catalogs (element-counted, never shrinking). The system-level trace can prove
one Node.id byte-identical at every hop from extractor pin to editor selection.
And the reports *about* the system were themselves audited: 1,201 claims
re-checked against disk, one false claim found and fixed, everything else
verified or honestly flagged unverifiable.

## The enforcement machinery (how it stays true)

- `run_all_suites.py` — one clean-state command, 19 suites, currently 19/19.
- `faultcheck/` — six deliberate defects planted in scratch copies; each must
  make the real suite fail with the guard's named class. 6/6 caught.
- `linegate.py` — every non-exempt source file ≤ 200 lines (0 offenders / 727),
  with an explicit, reasoned exemption manifest; itself fault-tested.
- The audit ledgers (`audit/`) — every file's claims verified, refuted-checked,
  and distilled into the purposes you'll read in Part III.

# Part II — Every remaining problem, deeply

Nothing here is hidden in the outputs — each item below already rides in the
system's own declarations. This is the consolidated, explained version.

## A. The seven declared limitations (operational debts)

**A1. Lean toolchain pin divergence (the one real *inconsistency*).**
The kernel driver pins `leanprover/lean4:v4.31.0` (chosen because two 4.31
behaviors were *measured* during the spike: the async `TheoremVal.value` read
and the processHeader log union). Cell 2's Lean capability testbed pins
`v4.32.0` (where CT was measured). So the system *measures* Lean's capability
on one kernel version and *verifies proofs* with another. Both pins are explicit
files; the divergence is probed on every CT run and rides every Lean output.
Why it matters: a proof accepted by 4.31 will, in practice, be accepted by
4.32 — but "in practice" is exactly the kind of claim this system refuses to
make silently, which is why it's flagged. The fix is mechanical but must be
done honestly: pick one pin, move the other side, and **re-measure** the moved
side (re-run the driver smoke or capability gate 17) rather than assuming the
measurements transfer. ~1–2 hours of machine time; low risk.

**A2. Lean is single-file.**
The driver elaborates one file per invocation. Real Lean *projects* (lake,
multi-file import graphs, Mathlib dependencies) are recommended-unproven: the
spike documented the likely path (`lake build` then `lake env lean --run` per
file) but no scratch lake project was ever built and proven. Consequence today:
the Mathlib-import fixture measures **red** (its header can't elaborate in
isolation) — honest, but a limitation of scope, not of the file. This is the
single biggest capability gap between "demo-real" and "world-real" Lean support.

**A3. The browser gutter at stub tier shows blocked greens.**
When the app runs against a hub without a measured capability stream (the
ephemeral test hubs), the editor mounts on cell 4's stub transport at tier G —
and cell 4's guard correctly *blocks* attested kernel greens from painting
green, because tier G is not compiler truth. You see unknown glyphs with
`wouldBeGreen:true` in the pins. This is the honesty machinery working exactly
as designed, but it means the *visual* green gutter requires the full
`--lsp live` stack; headless proof at measured CT covers the assertion.

**A4. Two environment quirks on this machine.**
(a) One hub subtest skips loudly where Windows denies symlink creation
(WinError 1314) — the path-escape class it tests is still covered by the
resolve-before-commonpath jail design. (b) The Monaco canvas screenshot hang:
`Page.captureScreenshot` can hang on this machine; the headless UI driver
simply never calls it (asserting via DOM/a11y/pins instead), and the screenshot
tool is retired to manual use. Neither affects correctness; both are recorded.

**A5. Duplicated pyright subprocess under V1.**
Cell 2 measures Python with its own pyright child; cell 3 builds its *own*
pyright backend rather than consuming cell 2's handle (the wall's
`CapabilityHandle.handle` is passed but unused — a cell-design friction noted
since the original inventory). Under the V1 vessel both trees can coexist.
Cost: memory/startup, not correctness; both are tree-killed at teardown.
The "right" fix (bridging cell 2's live handle into cell 3's backend socket)
was deliberately rejected as reaching into cytoplasm; it would be a cell-3
design change for a future round.

**A6. The graph-node skin is byte-fragile by design.**
The design-faithful node cards are app-side CSS keyed on cell 5's rendered DOM
classes. A future cell-5 markup change sheds the skin (cards fall back to the
cell's own styling — ugly, never wrong), and the skin's honesty tests assert on
`styles.css` bytes, which is why the sub-200 split kept that section
byte-intact. The alternative — moving design tokens into cell 5 as a labelled
change — is recorded, not taken.

**A7. Faultcheck scratch specifics.**
Scratch copies junction `node_modules` (link, not copy); fault (a) runs cell 3
`--fast` (the live-pyright oracle is exercised in the full suite instead);
faults (c)/(d) fail at module setup by design because those guards are
build-failing. These are bounds of the *test harness*, recorded so nobody
mistakes them for coverage gaps.

## B. The twelve code-side findings from the claim audit

These are places where **the code itself** diverges from its evident purpose or
its frozen descriptions. Per the audit's rules they were reported, never
patched (behavior-preserving round). All are low/info severity. Grouped:

**Real latent bugs (would bite on an unreached path):**

1. **`byok-arena/src/adapters/gemini/wire.ts`** — when replaying a *neutral*
   conversation history containing `role:"tool"` messages, the reshaper puts
   the tool call id into `functionResponse.name`. Gemini matches function
   responses by *function name*; the id belongs in the separate `id` field. The
   cell's own `submitToolResults` path never hits this (it reconstructs from
   cache), so it's unreached today — but any future consumer replaying neutral
   histories through `chat()` on a real wire would mismatch. **Fix**: map
   name←functionName, id←toolCallId; add a wire-shape test. Small.
2. **`outerwall/analyze_roots.py`** — declared roots must never be guessed, and
   an unresolvable root raises `unknown-root`. True for module *names* — but
   the module-*ID* branch expands a module node with zero decl members to `[]`
   silently, so an all-module-ID root set proceeds with
   `gapAnalysis.undeclared=true` despite roots having been declared. The
   equivalent name spelling raises. Inconsistent honesty on an untested path.
   **Fix**: make the ID branch raise the same class; add the fixture. Small.
3. **`graph-view/src/ingestEdges.ts`** — the duplicate-edge-id rejection branch
   is dead (`seenEdgeIds` never populated); duplicates are only caught
   downstream at renderGate as a thrown violation. The invariant *is* enforced,
   at the wrong layer with the wrong failure mode (throw vs probed rejection).
   Pre-documented; fix is a two-line populate + test.

**Honesty drift in probe/catalog descriptions (docs frozen as runtime data):**

4. **`structure-extractor/extractor/ingest.py`** — the `dock.selected` probe
   reason still calls every non-python dock a "design-stub … leads only";
   Lean's dock has been CT with kernel greens for two rounds. The *frozen
   catalog contract* (element identity) is why the audit left runtime payloads
   alone; the honest fix is a catalog revision treated as a schema-style
   amendment, not a drive-by edit.
5. Same file — the no-lakefile project-root reason says the Lean dock "would
   need a Lake project when live"; it is live, single-file, needing none.
6. **`graph-model/src/probe/leads_analysis.py`** — two catalog descriptions say
   round-trip IDs are recovered by "re-ingesting the reprint"; reality is
   `ids_from_manifest(manifest)` — the reprint's bytes are never parsed. The
   *check itself* is still meaningful (it pins byte-independence of identity),
   but the description oversells the mechanism. Known since the original
   inventory; same catalog-amendment path to fix.
7. **`capability-layer/capability/probe_p6_p11.py`** — P11 poses "persisted
   index (fast) or re-derived?" as a measured question but hardcodes
   `restart_fast=False`; the answer happens to be true for all current servers,
   but it is asserted, not measured. Fix: actually time the restart.

**Spec-conformance / dead-parameter findings:**

8. **`capability-layer/capability/spine_proto.py`** — `didChange` always stamps
   LSP version 2; a second change re-sends v2. Spec-nonconforming for servers
   enforcing monotonic versions; tolerated by all three servers used. Fix: a
   counter. (Battery waits filter on version, so the fix must touch both.)
9. **`editor-shell/src/mount/mount.ts`** — `wrapper.ready` promises
   `msSinceInit`; the private init wall is dead and the value is always null.
10. **`editor-shell/src/probe/catalog/select-map.ts`** — `emit.multi` declares
    a `'primary-caret'|'all'` policy space; only `'primary-caret'` exists.
11. **`editor-shell/src/buffer/open-probes.ts`** — `size.cap` declares
    `'open'|'degrade'`; no degradation path exists (the payload honestly says
    so — this one is info-grade future-bound documentation).
12. **`hub/server_ws.py`** — the module family claims "all logged, never
    silent", but the WS bridge loop's bare `except Exception: pass` swallows
    `backend.start()` and frame-handler errors with no named-class emit (only
    the generic close fires in `finally`). The *loss* classes exist
    (`lsp-bridge-drop`, `lsp-backend-dead`); this specific swallow predates
    them. Fix: emit a named class in the handler. Small, worth doing.

## C. Structural debts (deliberate scope, waiting for their round)

- **Probe-event contract ×4** — ProbeEvent/CatalogEntry are implemented
  independently in four cells with zero drift found; unification into a shared
  package was deferred in Phase 0 as hygiene-not-repair. Still true.
- **byok-arena**: the OpenAI Responses-API adapter is a stub branch; streaming
  is not implemented (logged, non-silent); the vault is in-memory only; the
  price table is a dossier snapshot. All declared in its ceiling.
- **Language coverage honesty**: LaTeX and Typst docks remain design-stubs
  (tier G, leads only — the typst fixture *is* the system's unknown-never-green
  acceptance story); Go/C/C++ are structure-only (no T2 dock); cell 2 still
  carries its three original stand-in languages (ybg/awk/zigish) as its own
  test fixtures alongside measured python and lean.
- **One-document editor**: cell 4 is one document per instance (tab switch =
  dispose+mount, by design); cross-file editing depth is a future cell round.
- **Single workspace per hub**: the hub serves one declared workspace; the
  app's project switcher re-analyzes rather than multiplexing.
- **AI outlet is one tool-round deep** (bound logged) and FAKE-transport in
  every demo path; `--live` requires a key in the server process only.
- **The audit's own horizon**: ~30 historical claims in the reports are flagged
  unverifiable-cheaply (one-shot live observations like a 75.9s cold start);
  they are marked as such in the ledgers rather than re-asserted.

## D. If you fix five things next (my priority order)

1. **Unify the Lean toolchain pin + re-measure** (A1) — removes the one genuine
   inconsistency; everything else stands on it.
2. **Multi-file Lean via a proven lake path** (A2) — the capability gap between
   demo and world; makes Mathlib-adjacent projects analyzable.
3. **The `server_ws.py` silent swallow + the two real latent bugs** (B12, B1,
   B2) — three small fixes that close every "code lies" finding that could
   actually bite.
4. **Catalog revision round** (B4–B7, B9–B11) — a single schema-style amendment
   pass that re-freezes the probe catalogs with truthful descriptions (counts
   may grow, never shrink), so the frozen-data honesty debt is retired.
5. **Cell-3 consumes cell 2's handle** (A5) — the last piece of cytoplasm-level
   friction from the original parallel build.
